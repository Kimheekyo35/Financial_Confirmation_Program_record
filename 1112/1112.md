## Streamlit 배포하기

### VM 에서 port 생성하여 배포할 계획

1. VM -> Networking -> Add inbound security rule
- inbound란? 밖에서 VM으로 들어오는 트래픽을 뜻함. 그러면 Outbound은 VM에서 나가는 트래픽.
- inbound 규칙. 누가 내 VM에 접속할 수 있는 지를 정함. 예를 들어 SSH(22) 번으로 들어오는 접속이나, 브라우저 streamlit (8501번) 에 들어오는 접속이 해당함. 규칙에 없으면 기본적으로 막힘.
- Outbound 규칙. VM이 밖으로 나가는 걸 정함. pip install 이나 DB 접속 같은 요청이 해당하고, 기본적으로 대부분 허용되어있어 건드릴 필요 없음

-> 내가 만드는 streamlit은 inbound이므로 inbound설정만 하면 됨.

> source = Any (누구나 접속 허용) 또는 IP Addresses (특정 IP만)

> Source port ranges = *(기본값 그대로)

> Destination = Any(기본)

> Service = Custom

> Destination port ranges = 8501

> Protocol = 8501

> Action = Allow

> Priority = 기본값 그대로 (예: 310). 기존 규칙보다 숫자가 작을수록 우선입니다.

> Name = 알아보기 쉬운 이름

### TCP란?
- TCP(Transmission Control Protocol) 는 데이터를 주고받을 때 쓰는 통신 규칙(프로토콜)의 하나임. 상대와 먼저 연결을 맺고, 데이터가 빠지거나 순서가 뒤바뀌지 않았는지 확인하면서 보냄. **신뢰성이 필요한 통신에 쓰임**

- TCP를 쓰는 것: 웹 브라우징(HTTP/HTTPS), SSH, PostgreSQL, Streamlit 등
- UDP: TCP와 달리 연결 확인 없이 빠르게 보내는 방식. 영상 스트리밍이나 DNS 같은 곳

streamlit은 둘 다 가능하지만, 필요한 것만 열어두는 TCP가 남.

-> streamlit run app.py --server.port 8501 --server.address 0.0.0.0 
한 후, http://57.151.98.166:8501/ 를 클릭하면 열려야하는데 안 열림..

핸드폰으로 해도 안 열림.

1. 방화벽? sudo ufw status -> inactive 로 뜸
2. ss -tlnp | grep 8501 -> 8501번 포트를 어떤 프로세스가 실제로 열고(LISTEN) 있는지 확인하는 것 0.0.0.0로 잘 열려있었음......
3. 회사 내부망 문제? -> 핸드폰으로 들어가도 안 들어가짐.

그렇다면, 로컬 powershell에서
`Test-NetConnection 57.151.98.166 -Port 8501` 로 한 결과, TcpTestSuccedd : False 로 나옴. **NSG에서 막힌 것.**
=> **NSG (Network Security Group) 는 Azure VM 앞에 있는 출입문 / 방화벽임.**

```
VM 공인 IP:8501
      ↓
❌ NSG 차단
      ↓
Streamlit까지 못 감
```

Azure NSG 에서는 숫자가 작을수록 먼저 검사하는데, priority를 이전에 4010 줬더니 이전 **특정 트래픽에서 DENY** 가 걸려, 8501 포트의 규칙까지 오지 못함.
**Priority 4010 -> 330**으로 수정하여 오류 해결.
