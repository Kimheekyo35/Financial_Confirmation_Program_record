## AWS-SAA
- EC2 : 내 컴퓨터
- EBS : 내 컴퓨터에 붙은 외장 하드디스크 같은 거 (SDD)
- S3 : 클라우드 저장소 (google drive 같은 거)
- RDS : postgreSQL, mySQL 같은 DB (관계형 데이터 베이스 시스템, Relational Database system)
- VPC (virtual private cloud): AWS 안에서 만든 내 네트워크
    - VPC를 여러 네트워크 영역으로 나눈 것이 Subnet. EC2를 외부에서 직접 접근하지 못하게 하려면 private Subnet에 배치함.

```
VPC
│
├── Public Subnet
│    └── EC2  ← 인터넷에서 직접 접근 가능하게 구성할 수 있음
│
└── Private Subnet
     └── EC2  ← 인터넷에서 직접 접근 불가능
```

- NAT Gateway : Private Subnet이 밖으로 
### Security group / IAM
- **Security group** : 네트워크 통신에 대한 권한
- **IAM** : RDS, API 등 AWS에서 '내'가 할 수 있는 것 (권한 부여받은 것)

### NACL (security group과 유사하지만, subnet에 적용됨)
-> NACL(Network Access Control List) 은 Subnet 단위에서 네트워크 트래픽을 허용/차단하는 규칙

```
               Internet
                  │
                  ↓
          ┌───── NACL ─────┐  ← Subnet 입구
          │    Subnet      │
          │                │
          │   ┌─ SG ─┐     │
          │   │ EC2  │     │
          │   └──────┘     │
          │                │
          └────────────────┘
```

- Security group = stateful (들어오는 요청을 허용했다면 그 요청에 대한 응답 트래픽을 기억함.)
- 하지만 NACL (=Stateless) 은 그런 상태를 기억하지 않음. Inbound/Outbound 각각 고려해야 함.

### DNS / Route 53
- DNS = Domain Name System (도메인 이름을 IP주솔로 바꿔주는 인터넷 전화번호부)

**AWS에서 DNS 기능을 제공하는 서비스 이름이 Route53** 임.

그치만 DNS=Route53 은 아니고 Route53 말고도 DNS 서비스들이 있음.
```
www.myapp.com
      ↓
 Route 53 (DNS)
      ↓
     ALB
   ↙     ↘
 /api   /images
   ↓       ↓
 EC2      EC2

```

### Cloudtrail / Cloudwatch
- **Cloudtrail** : Cloudtrail은 흔적, 자취 라는 뜻으로 AWS에서 **누가 무엇을 했는지** 에 대한 활동 기록
- **CloudWatch** : AWS 리소스/애플리케이션이 **지금 어떻게 돌아가고 있는지** 에 대한 **모니터링**

### CloudFront
- **CloudFront** : Front => 누군가의 앞에 있는 것, 사용자와 가까운 **Edge Location** 을 활용해서 콘텐츠를 **빠르게** 전달하는 개념

### EFS
- EFS = Elastic File System
- 여러 EC2가 공유해서 사용할 수 있는 파일 시스템
- 회사 공용 네트워크 드라이브와 비슷함

```
EC2-A ─┐
EC2-B ─┼──→ EFS
EC2-C ─┘    │
             ├── /images
             ├── /data
             └── /files
```

### ElasticCache
- DB 앞에 두는 초고속 메모리 캐시

```
요청 → RDS
요청 → RDS
요청 → RDS
요청 → RDS

→ 똑같은 조회 때문에 DB가 바빠짐

자주 조회하는 결과를 ElasticCache의 메모리에 임시 저장하면

              ┌→ ElastiCache ✅ 있으면 바로 반환
사용자 → EC2 ─┤
              └→ RDS       없으면 DB에서 조회

메모리 기반이라 빠르고, RDS에 반복적으로 가는 요청도 줄일 수 있음
```

### EventBridge
- “이런 이벤트가 발생하면 → 이쪽으로 보내!”라는 이벤트 교통정리 서비스

```
        주문 생성 이벤트
            ↓
        EventBridge
             │
       규칙에 따라 판단
    ↙         ↓        ↘
  결제        배송       분석
Lambda       SQS      Lambda
```
