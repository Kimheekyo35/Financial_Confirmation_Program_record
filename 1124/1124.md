### S3 Transfer acceleration

1. S3 Transfer acceleration은 **멀리 떨어진 사용자와 S3 버킷 사이의 파일 전송을 빠르게 해주는 기능**

- Multipart Upload : 큰 파일을 여러 조각으로 나누어 병렬 업로드
- CloudFront : 콘텐츠를 엣지에 캐싱해서 사용자에게 빠르게 제공

-> **S3 Transfer acceleration**과 **Multipart Upload**는 함께 사용 가능함. 큰 파일을 조각내서 병렬로 보내면서, 전송 경로도 최적화하는 것.

### CloudFront와 Transfer Acceleration의 차이
- **CloudFront**: 이미지, 영상 등을 가까운 엣지에서 사용자에게 빠르게 제공하는 서비스. **캐싱**이 핵심
- **S3 transfer** : 사용자와 S3 사이의 장거리 업로드와 다운로드를 빠르게 하는 기능. **전송 경로 최적화**가 핵심


### Snowball Edge Storage Optimized
- Snowball Egde Storage Optimized는 대용량 데이터를 담아 AWS로 배송하는 **실물 저장 장비**. 

① AWS가 빈 Snowball 장비를 현장으로 배송

② 회사가 장비에 데이터를 복사

③ 장비를 AWS로 반송

④ AWS가 장비의 데이터를 S3에 업로드

Snowball은 실제로 만지고 운반할 수 있는 물리적인 장비. 실제로 AWS에서 장비를 배송하면 회사에서 케이블로 연결해 데이터를 복사하고 AWS로 반송하여 AWS가 S3에 데이터를 적재하는 파이프라인!

### Amazon Athena vs Amazon Redshift vs AWS Glue vs Amazon EMR vs Apache Spark
- Amazon Athena : S3 파일을 SQL로 조회하는 도구
- Amazon Redshift : 분석용 데이터베이스인 **데이터 웨어하우스**
- AWS Glue : 데이터를 정리 및 변환하고, 구조를 등록하는 서비스
- Amazon EMR : Spark 같은 빅데이터 처리 도구를 AWS에서 실행하는 서비스
- Aparche Spark : 대량의 데이터를 여러 컴퓨터에 나눠 처리하는 엔진

## 4번

```
애플리케이션은 VPC의 Amazon EC2 인스턴스에서 실행됩니다. 애플리케이션은 Amazon S3 버킷에 저장된 로그를 처리합니다. EC2 인스턴스는 인터넷에 연결하지 않고 S3 버킷에 액세스해야 합니다. Amazon S3에 프라이빗 네트워크 연결을 제공하는 솔루션은 무엇입니까?

① A. S3 버킷에 대한 게이트웨이 VPC 엔드포인트를 생성합니다.
② B. 로그를 Amazon CloudWatch Logs로 스트리밍합니다. 로그를 S3 버킷으로 내보냅니다.
③ C. S3 액세스를 허용하려면 Amazon EC2에 인스턴스 프로필을 생성합니다.
④ D. S3 엔드포인트에 액세스하기 위한 프라이빗 링크가 포함된 Amazon API Gateway API를 생성합니다.
```
**정답: 1**

해당 문제에서 알아야 할 부분은 **인터넷에 연결하지 않고 S3 버킷에 액세스**. 

- 1번, **인터넷 없이 S3에 접근하는 네트워크 경로를 제공**하므로 정답
- 2번, 로그를 옮기는 방법이며 EC2와 S3 사이의 연결을 해결하지 못함
- 3번, S3에 접근할 권한을 부여하지만, 네트워크 경로는 만들지 않음
- 4번, API gateway를 추가할 필요가 없음. 

### 엔드포인트, 인스턴스, 게이트웨이
- **인스턴스 (Instance)** = 빌려쓰는 컴퓨터 한 대
- **VPC = AWS 안에 만든 나만의 네트워크**
- **게이트웨이 (gateway)** = 다른 네트워크로 나가는 관문
- **엔드포인트 (endpoint)** = 특정 서비스에 접근하는 접점
    - "어디로 요청을 보내면 그 서비스를 사용할 수 있는가?"에 해당하는 접점
    - **VPC 엔드포인트는 내 VPC에서 S3 같은 AWS 서비스에 인터넷을 거치지 않고 접근**하도록 연결해줌

## 9번
```
한 회사가 데이터 센터에서 SMB 파일 서버를 운영하고 있습니다. 파일 서버는 파일이 생성된 후 처음 며칠 동안 자주 액세스되는 대용량 파일을 저장합니다. 7일 후에는 파일에 거의 액세스되지 않습니다.
전체 데이터 크기가 점점 늘어나 회사의 전체 저장 용량에 가까워지고 있습니다. 솔루션 설계자는 가장 최근에 액세스한 파일에 대한 짧은 대기 시간의 액세스를 잃지 않으면서 회사의 사용 가능한 저장 공간을 늘려야 합니다. 솔루션 설계자는 향후 스토리지 문제를 방지하기 위해 파일 수명주기 관리도 제공해야 합니다.
이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

① A. AWS DataSync를 사용하여 SMB 파일 서버에서 AWS로 7일보다 오래된 데이터를 복사합니다.
② B. Amazon S3 파일 게이트웨이를 생성하여 회사의 저장 공간을 확장합니다. 7일 후에 데이터를 S3 Glacier Deep Archive로 전환하는 S3 수명 주기 정책을 생성합니다.
③ C. 회사의 저장 공간을 확장하기 위해 Amazon FSx for Windows File Server 파일 시스템을 생성합니다.
④ D. 각 사용자의 컴퓨터에 유틸리티를 설치하여 Amazon S3에 액세스합니다. 7일 후에 데이터를 S3 Glacier 유연한 검색으로 전환하는 S3 수명 주기 정책을 생성합니다.
```
**정답: 2번**

### AWS DataSync & S3 Glacier Deep Archive & Amazon FSx for Windows File Server
- **AWS DataSync** : 데이터를 옮겨 주는 이사업체 (회사에 있는 파일을 S3나 EFS 같은 AWS 저장소로 **복사 및 전송하는 서비스**, 많은 파일을 옮길 때 전송과 검증 작업을 자동화해 줌)
    - 회사 파일 서버 ── DataSync ──→ S3
- **S3 Glacier Deep Archive** : S3에는 사용 빈도에 따라 여러 **저장 등급** 이 있음. Deep Archive는 그중 **오랫동안 보관하고, 거의 읽지 않는 데이터**에 적합한 **저렴한 등급**임. (※ Archive= 기록 보관소 라는 뜻)
- **Amazon FSx for Windows File Server** : AWS가 운영해주는 window 공유 파일 서버 (Windows 공유 폴더를 AWS에서 제공하는 서비스)
    - 파일을 옮기는 DataSync와 달리, **옮겨 놓고 계속 사용할 파일 서버 자체를 제공함.**

### S3 파일 게이트 웨이
- **로컬 캐시 기능**을 포함함.
- **파일 게이트웨이**는 **회사에서 쓰는 공유 폴더와 S3를 연결하는 중간 역할**을 함.
- ★ 로컬 캐시가 있으면 → 회사 쪽 저장장치에서 바로 읽으니 빠름
- ★ 로컬 캐시가 없으면 → S3에서 가져와서 읽음 (단, Deep Archive에 있는 건 복원 필요)


## 10번
```
한 회사가 AWS에서 전자상거래 웹 애플리케이션을 구축하고 있습니다. 애플리케이션은 새로운 주문에 대한 정보를 Amazon API Gateway REST API로 보내 처리합니다. 회사는 주문이 접수된 순서대로 처리되기를 원합니다. 이러한 요구 사항을 충족하는 솔루션은 무엇입니까?

① A. 애플리케이션이 주문을 수신하면 API Gateway 통합을 사용하여 Amazon Simple 알림 서비스(Amazon SNS) 주제에 메시지를 게시합니다. 처리를 수행하려면 주제에 대한 AWS Lambda 함수를 구독하세요.
② B. 애플리케이션이 주문을 받으면 API 게이트웨이 통합을 사용하여 Amazon Simple Queue Service(Amazon SQS) FIFO 대기열에 메시지를 보냅니다. 처리를 위해 AWS Lambda 함수를 호출하도록 SQS FIFO 대기열을 구성합니다.
③ C. API 게이트웨이 권한 부여자를 사용하여 애플리케이션이 주문을 처리하는 동안 모든 요청을 차단합니다.
④ D. 애플리케이션이 주문을 받으면 API 게이트웨이 통합을 사용하여 Amazon Simple Queue Service(Amazon SQS) 표준 대기열에 메시지를 보냅니다. 처리를 위해 AWS Lambda 함수를 호출하도록 SQS 표준 대기열을 구성합니다.
```

### Lambda 함수
- 위 회사에서 Lambda 함수가 필요한 이유는
```
API Gateway ▶ 주문 요청을 받음
     ↓
SQS FIFO ▶ 주문을 접수 순서대로 대기시킴
     ↓
  Lambda ▶ 주문을 꺼내 실제 처리 코드를 실행 
```
- **Lambda함수**는 자기 차례가 되면 자동으로 실행되는 코드로 이해하면 됨.
